# PUMA 560 project: methods, assumptions and results

This document explains the mathematical models and algorithms (a course requirement) and
states which parts are student NumPy code and which use MuJoCo. Numbers are regenerated by
`python run_experiments.py && python analyse_results.py` (fixed seeds, deterministic).

## 0. What is implemented by whom

| Area | Implementation | MuJoCo role |
|---|---|---|
| DH model, FK, analytic IK (8 branches), Jacobian, singularities | NumPy (`src/dh_model.py`, `forward_kinematics.py`, `inverse_kinematics.py`, `jacobian.py`, `singularity_analysis.py`) | independent verification only |

## 1. Robot model and dynamics
Standard-DH PUMA 560 (Corke & Armstrong-Helouvry 1994 parameters), spherical wrist, closed-form IK.
Rigid-body model `M(q) qdd + C(q,qd) qd + g(q) + B qd = tau` (+ contact forces). MuJoCo integrates it
(`implicitfast`, dt = 2 ms). **Assumed, not PUMA specifications:** viscous damping B = 1 N m s/rad per joint,
torque limits [150, 150, 100, 30, 20, 10] N m, collision capsules, link-1 placeholder mass 1 g,
link-3 inertia corrected to satisfy the triangle inequality, no Coulomb friction / rotor inertia / motor model.
See `models/LICENSE_NOTICE.md` and `PART1.md`.

**Consequence worth knowing:** the wrist inertias are tiny (joint 6 about 4e-5 kg m^2), so with B = 1 the wrist
joints are strongly damping dominated (first-order). Wrist tracking is limited by the viscous lag `b qd_des / Kp`.

## 2. Gravity compensation
`g_hat(q) = - sum_l Jv_cl(q)^T m_l g_w`, `Jv_cl[:, i] = z_{i-1} x (p_cl - p_{i-1})` for `i <= l`, with
`p_cl = T_0l [c_l; 1]`. This is the torque that cancels gravity (`tau = g_hat` holds the arm still).
Optional rigid payload = one more body on frame {6}. Verified against MuJoCo `qfrc_bias` at random poses, with and
without payload (`tests/test_control.py`).

## 3. Path planning (`src/path_planning.py`)
* **Direct**: `q(s) = q_s + s (q_g - q_s)`, accepted only if every sampled configuration on it is valid.
* **RRT** (single tree, goal bias 10 %) and **RRT-Connect** (two trees; one extends, the other greedily connects).
  Step 0.2 rad, edge check every <= 0.02 rad per joint, nearest neighbour = Euclidean joint distance.
* **Shortcut smoothing**: 150 random collision-checked shortcuts between non-adjacent waypoints.
* Every call returns a `PlanResult` (status, time, iterations, seed, path length). The same seed reproduces the path.
* **Limits:** discrete (not continuous) edge checking; probabilistic, not optimal or complete; unweighted joint metric.
  Mitigation: planning uses obstacles **inflated by 3 cm**; the final timed trajectory is re-checked at fine
  resolution against the **true** obstacles; executed motion is checked for real contacts.

Task layer (`src/tasks.py`): target pose -> IK (8 branches) -> reject joint-limit / collision-infeasible branches ->
nearest remaining branch -> plan -> quintic trajectory -> verification.

## 4. Trajectory generation (`src/trajectory.py`)
Per segment of duration `T`, `u = t/T`, `s(u) = 10u^3 - 15u^4 + 6u^5`, `q_d = q_a + (q_b - q_a) s(u)`,
`qd_d = (q_b - q_a) s'(u)/T`, `qdd_d = (q_b - q_a) s''(u)/T^2` (rest-to-rest, zero velocity and acceleration at the
ends). `max s' = 1.875`, `max |s''| = 10/sqrt(3)`, so `T = max_i max(1.875 |dq_i|/vmax_i, sqrt(5.774 |dq_i|/amax_i))`.
Limits used: v = [0.8, 0.8, 0.8, 1.5, 1.5, 2.0] rad/s, a = [1.5, 1.5, 1.5, 5, 5, 8] rad/s^2. The robot **stops at every
waypoint** (simple, but slower than a blended trajectory; accepted limitation).

## 5. Controllers (`src/control.py`)
`e = q_d - q`, `e_dot = qd_d - qd`
* **PD**: `tau = Kp e + Kd e_dot`
* **PD + gravity**: `tau = Kp e + Kd e_dot + g_hat(q)` (evaluated at the measured q)

Both share one interface and are selected by configuration; torque is clipped to the actuator limits by the
simulator interface and both requested and applied torque are logged. Control rate = physics rate = 500 Hz.

**Why PD(+G):** model-free apart from the gravity term, per-joint tunable, and with gravity cancelled the set-point
regulation is globally asymptotically stable (Takegaki & Arimoto 1981). Without `g_hat` the equilibrium shifts by about
`Kp^-1 g(q)`; the comparison measures exactly that.

**Gains** (`DEFAULT_KP`, `DEFAULT_KD`): `Kp = [600, 550, 225, 20, 20, 20]`, `Kd = [100, 80, 17, 0.5, 0.2, 0.01]`.
Joints 1-3: `Kp = I_max wn^2`, `Kd = 2 zeta wn I_max - b` with wn = 12/14/25 rad/s and zeta = 1 (critical damping at the
largest inertia). Joints 4-6: damping dominated, Kp sets the closed-loop time constant `(b + Kd)/Kp` ~ 50 ms, Kd limited
by the explicit-derivative stability cap `Kd <= I_min/dt`. Tuning evidence: `tools/tune_gains.py` ->
`results/tuning/` (design table + 27-run sweep). Findings: error falls as 1/Kp, Kd has little effect, behaviour stays
good up to ~32x the design gains and degrades at 64x (sustained saturation). The margin is a *simulation* margin (perfect
state, no delay or noise).

## 6. Experiments (all in `run_experiments.py`)
Task: tool-down pick-and-place sweep from `q_s = (-0.6, 0.4, -2.5, 0, -1.0, 0)` to the pose
`xyz = (0.742, 0.337, 0.807) m`, `rpy = (149.1, 16.7, 174.1) deg` (IK -> `q_g = (0.6, 0.6, -2.3, 0.3, -0.9, 0.5)`).

| # | condition | what changes |
|---|---|---|
| 1 | nominal | free space, nominal model |
| 2 | obstacle (challenging) | floor-standing pillar (0.2 x 0.2 x 0.7 m at (0.76, -0.15)) blocks the direct path; RRT-Connect detour |
| 3 | payload (challenging) | 2 kg box on the flange; controller gravity model **not** updated |
| extra | payload-aware | same as 3 with a gravity model that knows the payload (clearly labelled) |

### Comparative studies (quantitative)
**A. PD vs PD + gravity** (identical start, reference, gains, limits, 2 s settling hold, same metrics):

| experiment | controller | RMSE [rad] | final EE error [mm] | collision-free |
|---|---|---|---|---|
| nominal | PD | 0.0333 | 75.2 | yes |
| nominal | PD + G | 0.0041 | 0.0 | yes |
| obstacle | PD | 0.1603 | 75.2 | **no** (links 5, 6 hit the pillar, 1.6 s torque saturation) |
| obstacle | PD + G | 0.0062 | 0.0 | yes |
| payload | PD | 0.0516 | 115.8 | yes |
| payload | PD + G (nominal model) | 0.0244 | 42.4 | yes |
| payload | PD + G (payload-aware) | 0.0046 | 0.0 | yes |

Interpretation: gravity compensation removes the steady-state sag (about 0.07 rad on joints 2 and 3). That sag
lowers the wrist by roughly 6 cm, more than the 4 cm planned clearance, which is why PD alone collides with the pillar.
With an unmodelled payload the compensated controller is still better than PD but no longer holds the target within tolerance;
updating the model removes the residual. This is one task and one gain set; it does not prove PD+G is universally superior.

**B. Planner comparison** (obstacle task, 20 seeds each, 20 s timeout): RRT-Connect 20/20, median 0.15 s,
median path 1.52 rad; RRT 16/20, median 0.22 s (up to 2.3 s), median path 1.71 rad. Success counts, path
lengths and iteration counts are deterministic; wall-clock times vary by machine. The direct path fails (blocked).

**C. Gain sensitivity** (parameter-setting study): `results/tuning/sweep.md`.

## 7. Known limitations (be honest in the report)
* Simplified collision proxies, not the visual meshes; discrete collision checking.
* Stop-and-go trajectory at waypoints; no time-optimal or blended timing.
* Viscous damping and torque limits are teaching assumptions; the wrist gains depend on the 1 N m s/rad damping.
* Control uses exact simulator state (no noise or delay).
* Single task geometry; the payload COM/inertia are assumed values.
* Inverse dynamics / computed torque is not implemented (optional extension).
